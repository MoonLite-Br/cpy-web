How

How the interpreter is put together.

Pipeline

  1. Lexer / parser — source → AST
  2. Resolver — names bound to local slots, free vars, globals
  3. Execution — tree-walk by default; hot functions may run on the bytecode VM
  4. Runtime — refcounted values, method-dispatch cache, embedded modules

Name resolution

At compile/resolve time, local variables become fixed array indices. That avoids a dict probe on every read/write inside a function — a major reason tight loops feel light compared to a pure dict-based frame.

Generators

When ucontext (or the sigaltstack fallback) is available, generators switch stacks in userspace instead of allocating a full OS thread per generator. Without those, a slower thread-based path still works.

Method cache (1.11+)

Attribute nodes can remember the last builtin-type method they resolved (str/list/…). Matching type tags reuse the cached method value on the hot path.
