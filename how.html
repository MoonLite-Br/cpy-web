How

How the interpreter is structured.

Pipeline

  1. Lexer / parser — source → AST
  2. Resolver — locals become fixed array slots
  3. Execution — tree-walk, or bytecode VM on hot functions
  4. Runtime — refcounted values, method cache, embedded modules

Design notes

  • Resolved locals avoid dict probes on every variable access.
  • Generators can use userspace stack switch (ucontext / sigaltstack).
  • v1.11 adds an inline method-dispatch cache for hot attribute calls.
